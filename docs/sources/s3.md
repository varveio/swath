# Amazon S3 and S3-compatible stores

`s3://BUCKET[/PREFIX]` lists the current objects of a general-purpose bucket, or those whose keys start with
the prefix; `--all-versions` lists every version and delete marker. With `--endpoint-url` the same source
lists an S3-compatible store.

## The smallest command

A public NOAA prefix, with no AWS account:

```bash
swath du s3://noaa-gestofs-pds/stofs_2d_glo.20230113/ -d 1 --anonymous --s3-region us-east-1
```

Without `--anonymous` swath signs its requests with your AWS credentials.

## Authentication and permissions

**Permissions.** `s3:ListBucket` on the bucket; `s3:ListBucketVersions` with `--all-versions` (swath never
falls back to a current-object listing when it is refused).

**Credentials.** The AWS SDK's default chain: environment keys (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`,
`AWS_SESSION_TOKEN`), the shared `config` and `credentials` files and their profiles (`--s3-profile`, else
`AWS_PROFILE`), IAM Identity Center (SSO), web identity, `credential_process`, AssumeRole profiles, container
credentials (ECS, EKS Pod Identity) and EC2 instance roles (IMDSv2). The first lookup is waited for up to 30
seconds (a web-identity token file mounted late included). Refused before any request as configured but
broken: an access key without its secret or the reverse, a session token without both keys, `AWS_ROLE_ARN`
without `AWS_WEB_IDENTITY_TOKEN_FILE`, a profile that does not exist. Rules shared by every object store are in
[Choose a source](README.md#credentials-on-every-object-store).

**Region.** `--s3-region`, else `AWS_REGION`, `AWS_DEFAULT_REGION`, the profile's `region`, else `us-east-1`.
swath does not discover a bucket's region: a request to the wrong one fails with an error that names the
bucket's region and the option to give (`--s3-region eu-west-1`). STS calls use the environment's or the
profile's region, not `--s3-region`.

## Options for this source

- `--s3-requester-pays` accepts the request charges of a requester-pays bucket.
- `--s3-fetch-owner` fills the `owner_id` and `owner_display_name` columns.
- `--s3-fips` and `--s3-dualstack` (else `AWS_USE_FIPS_ENDPOINT`, `AWS_USE_DUALSTACK_ENDPOINT`) select AWS's
  FIPS and dual-stack endpoints; they are refused with a custom endpoint.
- `--s3-bearer-token-command COMMAND` sends an OAuth token instead of SigV4, for an S3-compatible endpoint
  that takes one, such as GCS's XML API. The command runs under `/bin/sh -c` (on Windows `cmd.exe /d /s /c`);
  its one line of output is sent as `Authorization: Bearer TOKEN`, and no AWS credential is looked up. It
  runs again after `--s3-bearer-token-refresh-interval` (45 minutes by default). A command that fails, runs
  past 30 seconds, or prints nothing or more than one line fails the request with cause `auth`.

## S3-compatible stores

Give the store's URL and, usually, a region it accepts:

```bash
swath list s3://bucket --endpoint-url http://127.0.0.1:9000 --s3-region us-east-1
```

Without `--endpoint-url`, `AWS_ENDPOINT_URL_S3`, else `AWS_ENDPOINT_URL`, is the endpoint (unless
`AWS_IGNORE_CONFIGURED_ENDPOINT_URLS` is `true`). A custom endpoint is addressed path-style
(`https://host/BUCKET`); `--no-s3-path-style` addresses the bucket in the host name instead, and
`--s3-path-style` uses the path on AWS's own endpoint. Requests are signed with SigV4 for the region given.
`AWS_CA_BUNDLE` is the CA bundle when `--ca-bundle` is not given.

The store must answer `ListObjectsV2` as S3 does: in ascending byte order of the key, with continuation
tokens. swath checks every page's order and refuses a service that breaks it (exit 1, cause `protocol`).
It trusts the store's listing answers, including an empty page (no keys, no continuation) inside a range
as the end of that range. A store that wrongly returns such a page makes swath silently miss keys: in
[#265](https://github.com/varveio/swath/issues/265), a pinned MinIO image returned one with later keys still
to come, and a listing missed 57% of the keys. Until the defense in #265 lands, compare the object count of a
first run against a new S3-compatible store with an independent count: the store's own metrics, or one
continuation-token chain with
[`swath diag list --sequential`](../internals/diagnostics.md).

## Writing a dataset to S3

`swath list SOURCE -o s3://BUCKET/PREFIX --work-dir DIR` puts the dataset in S3 and keeps only spill and the
run's metadata in `DIR` ([writing to a bucket](../production.md#writing-to-a-bucket)).

- **Credentials:** `--output-s3-profile NAME` (a shared config profile: keys, SSO, an assumed role, a
  credential process) or the AWS SDK's default chain; requests are always signed, whatever the source's
  `--anonymous` or `--s3-profile`. The default chain reads the same environment as the source's: give the
  destination a profile when the two must differ. The profile may change on resume.
- **Permissions:** on the bucket (`arn:aws:s3:::BUCKET`), `s3:ListBucket`: without it S3 answers a missing
  `manifest.json` with 403, not 404, and the fresh-prefix check fails. On the dataset's objects
  (`arn:aws:s3:::BUCKET/PREFIX/*`), `s3:PutObject`, `s3:GetObject`, `s3:DeleteObject` (orphans),
  `s3:AbortMultipartUpload` and `s3:ListMultipartUploadParts` (an abort's confirmation); in a versioned bucket
  also `s3:GetObjectVersion` and `s3:DeleteObjectVersion`.
- **Region and endpoint:** `--output-s3-region`, else `AWS_REGION`, `AWS_DEFAULT_REGION` or the profile's,
  else `us-east-1`; the one resolved, and `--output-endpoint-url` (an S3-compatible store, addressed
  path-style), are fixed for the run. The environment's endpoint variables (`AWS_ENDPOINT_URL`,
  `AWS_ENDPOINT_URL_S3`, FIPS, dual-stack) are never applied to the destination; a CA bundle is
  (`AWS_CA_BUNDLE`, or the profile's `ca_bundle`).
- **A lifecycle rule is required:** a part larger than 8 MiB is a multipart upload. A failed or cancelled
  upload is aborted and the abort confirmed, but one that a killed process leaves is not, nor one whose abort
  the bucket refused or did not confirm (the report's `output.remote.aborts_unconfirmed`), and S3 keeps an
  incomplete upload's parts, billed and invisible to listings, until it is aborted. Set a lifecycle rule that
  aborts incomplete multipart uploads (`AbortIncompleteMultipartUpload`, `DaysAfterInitiation` 1 or more) on
  the prefix or the bucket before writing to it.

## Limits and known differences

- Directory buckets (Express One Zone, names ending in `--x-s3`) are refused with exit 2; access points,
  Multi-Region Access Points and Outposts are not supported.
- A prefix is a string prefix: `s3://bucket/logs` covers `logs/` and `logs-old/`.
- The run report estimates request cost at AWS's reference rate only without an endpoint override.
