# Amazon S3 and S3-compatible stores

`s3://BUCKET[/PREFIX]` lists the current objects of a general-purpose bucket, or those whose keys start with
the prefix; `--all-versions` lists every version and delete marker. With `--endpoint-url` the same source
lists an S3-compatible store.

## The smallest command

A public NOAA prefix, with no AWS account:

```bash
swath du s3://noaa-gestofs-pds/stofs_2d_glo.20230113/ -d 1 --anonymous --s3-region us-east-1
```

Without `--anonymous` swath signs its requests with your AWS credentials.

## Authentication and permissions

**Permissions.** `s3:ListBucket` on the bucket; `s3:ListBucketVersions` with `--all-versions` (swath never
falls back to a current-object listing when it is refused).

**Credentials.** The AWS SDK's default chain: environment keys (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`,
`AWS_SESSION_TOKEN`), the shared `config` and `credentials` files and their profiles (`--s3-profile`, else
`AWS_PROFILE`), IAM Identity Center (SSO), web identity, `credential_process`, AssumeRole profiles, container
credentials (ECS, EKS Pod Identity) and EC2 instance roles (IMDSv2). The first lookup is waited for up to 30
seconds (a web-identity token file mounted late included). Refused before any request as configured but
broken: an access key without its secret or the reverse, a session token without both keys, `AWS_ROLE_ARN`
without `AWS_WEB_IDENTITY_TOKEN_FILE`, a profile that does not exist. Rules shared by every object store are in
[Choose a source](README.md#credentials-on-every-object-store).

**Long runs.** Credentials that expire (an assumed role, web identity, SSO, `credential_process`, container
credentials, an instance role) are refreshed before they expire: 5 minutes before, or when a quarter of
their lifetime is left if that is shorter. If S3 still answers that the token has expired, swath refreshes
them and sends the request once more. Keys that do not refresh
(`AWS_ACCESS_KEY_ID` with `AWS_SESSION_TOKEN`, or a profile's keys) are used as given: once they expire the
run stops with cause `auth` and says so. The run report counts the refreshes (`credentials.refreshes`) and
those an expired-token answer forced (`credentials.expired_refreshes`). The refresh is tested against fakes
only, and an upload to an S3 [dataset destination](#writing-a-dataset-to-s3) answered as expired fails
instead of being sent again ([known limits](../troubleshooting.md#known-limits)).

**Region.** `--s3-region`, else `AWS_REGION`, `AWS_DEFAULT_REGION`, the profile's `region`, else `us-east-1`,
never the EC2 instance metadata's region. swath does not discover a bucket's region: a request to the wrong one
fails with an error that names the bucket's region and the option to give (`--s3-region eu-west-1`). STS calls
use the environment's or the profile's region, not `--s3-region`.

## Options for this source

- `--s3-requester-pays` accepts the request charges of a requester-pays bucket.
- `--s3-fetch-owner` fills the `owner_id` and `owner_display_name` columns.
- `--s3-fips` and `--s3-dualstack` (else `AWS_USE_FIPS_ENDPOINT`, `AWS_USE_DUALSTACK_ENDPOINT`) select AWS's
  FIPS and dual-stack endpoints; they are refused with a custom endpoint.
- `--s3-bearer-token-command COMMAND` sends an OAuth token instead of SigV4, for an S3-compatible endpoint
  that takes one, such as GCS's XML API. The command runs under `/bin/sh -c` (on Windows `cmd.exe /d /s /c`);
  its one line of output is sent as `Authorization: Bearer TOKEN`, and no AWS credential is looked up. It
  runs again after `--s3-bearer-token-refresh-interval` (45 minutes by default). A command that fails, runs
  past 30 seconds, or prints nothing or more than one line fails the request with cause `auth`. The
  [published image](../install.md#container-images) has no shell, so the command cannot run in it: use the
  release binary, or an image of your own that adds a shell and the command's program.

## S3-compatible stores

Give the store's URL and, usually, a region it accepts:

```bash
swath list s3://bucket --endpoint-url http://127.0.0.1:9000 --s3-region us-east-1
```

Without `--endpoint-url`, `AWS_ENDPOINT_URL_S3`, else `AWS_ENDPOINT_URL`, is the endpoint (unless
`AWS_IGNORE_CONFIGURED_ENDPOINT_URLS` is `true`). A custom endpoint is addressed path-style
(`https://host/BUCKET`); `--no-s3-path-style` addresses the bucket in the host name instead, and
`--s3-path-style` uses the path on AWS's own endpoint. Requests are signed with SigV4 for the region given.
`AWS_CA_BUNDLE` is the CA bundle when `--ca-bundle` is not given. An `endpoint_url` in the shared `config`
file (a profile's, or its `services` section's) is not read: give the endpoint as `--endpoint-url` or
`AWS_ENDPOINT_URL_S3`.

**Proxies.** Requests to an `https://` endpoint, AWS's included, go through `HTTPS_PROXY` (or `https_proxy`);
`HTTP_PROXY` is used only for an `http://` endpoint. `NO_PROXY` lists hosts to reach directly, and a loopback
endpoint is never proxied. With only `HTTP_PROXY` set where the network allows no direct connection, requests
to AWS do not get through.

The store must answer `ListObjectsV2` as S3 does: in ascending byte order of the key, with continuation
tokens. swath checks every page's order and refuses a service that breaks it (exit 1, cause `protocol`).
It trusts the store's listing answers: a page with more keys than asked for (a response body up to 16 MiB) is
listed as it is.

**Stores that end a listing early.** swath lists ranges of keys in parallel, each from a start key
(`start-after`). S3 sends no end bound, so a page with no continuation token says that no key follows it.
Some S3-compatible stores answer a start key inside a folder with such a page, empty or short, while later
keys remain. MinIO does when more than about `max-keys` keys start with the folder's name followed by a
character that sorts before `/` (`logs-old/` beside `logs/`); a listing of 250,000 keys of `nara-1950-census`
on MinIO `RELEASE.2026-11-23T00-10-37Z` returned 107,651.

swath checks every such page. A key or folder the run has already listed past the page proves it wrong; when
there is none, one round trip of small requests in shapes these stores answer correctly asks whether any key
follows. Only keys modified before the run started count, so keys written at the end of the scope while it
lists do not keep it going. A page proved wrong is asked again, three times with a backoff, so that a key
deleted during the run, or a store whose listing lags its writes, does not fail the run. A store that keeps omitting the keys stops the run
with exit 1 and cause `omitted_keys`, naming the request and the key it left out. The run stays resumable: a
resume lists the same range again with the same check. On a store that answers correctly the check adds a few
requests a run: 1 to 6 on the AWS listings measured, of up to 62,557 keys
([measurements](../internals/measurements.md#the-end-check-of-s3-listings-2026-11-25)). The run report's `end_check` counters say what it checked
([Counters](../internals/counters.md); [Range engine](../internals/range-engine.md)).

Versions listings (`--all-versions`) are not checked yet. For those, or as an independent check of a store
before you rely on it, compare the object count of one prefix, not being written to, with a listing that
follows continuation tokens from the first key, such as the AWS CLI's:

```bash
swath du s3://bucket/prefix/ -d 0 --endpoint-url https://store.example --s3-region us-east-1
aws s3 ls s3://bucket/prefix/ --recursive --summarize --endpoint-url https://store.example | tail -2
```

The `objects` of swath's total row and the AWS CLI's `Total Objects` must be equal. Run it on the prefix you
intend to list: a small or unaffected prefix can pass on a store that fails elsewhere. Equal counts are a check,
not a proof: they do not show that every key was listed in order. Tracked in
[#265](https://github.com/varveio/swath/issues/265).

**Backblaze B2.** Use `--endpoint-url https://s3.REGION.backblazeb2.com --s3-region REGION`.

- **Current objects list as on S3.** B2 uses S3's byte order, and its start key and prefix behave as on S3.
- **Versions.** B2's `ListObjectVersions` pages differ from S3's: delete markers before versions, and a second
  `is_latest` on continuation pages. On a B2 endpoint swath puts them in S3's order and clears the false flag;
  the counters `b2.versions_reordered` and `b2.latest_cleared` show when it did.
- **No dataset output to B2.** A dataset can't be written to a B2 bucket ([below](#writing-a-dataset-to-s3)).
- **Refused keys.** B2 refuses keys holding a control character (0x01–0x1f) or DEL (0x7f), so they never exist
  there.
- **Keys of 1,024 bytes.** B2 refuses its own continuation token after a page that ends on a 1,024-byte key, which
  stops other clients there. swath restarts such a page itself (counter `b2.long_key_restarts`). A versions
  listing past such a key still stops with B2's error.
- **Throttling.** It answers `SlowDown` above a per-account request rate.

What was measured is in [the provider notes](../internals/providers/s3.md#s3-compatible-stores).

## Writing a dataset to S3

`-o s3://BUCKET/PREFIX --work-dir DIR` writes the dataset to S3; the command, what appears in the bucket and
how to resume and clean up are in [Writing to a bucket](../production.md#writing-to-a-bucket). What is S3's own:

- **Credentials:** `--output-s3-profile NAME` (a shared config profile: keys, SSO, an assumed role, a
  credential process) or the AWS SDK's default chain; requests are always signed, whatever the source's
  `--anonymous` or `--s3-profile`. The default chain reads the same environment as the source's: give the
  destination a profile when the two must differ. The profile may change on resume.
- **Permissions:** on the bucket (`arn:aws:s3:::BUCKET`), `s3:ListBucket`: without it S3 answers a missing
  `manifest.json` with 403, not 404, and the fresh-prefix check fails. On the dataset's objects
  (`arn:aws:s3:::BUCKET/PREFIX/*`), `s3:PutObject`, `s3:GetObject`, `s3:DeleteObject` (orphans),
  `s3:AbortMultipartUpload` and `s3:ListMultipartUploadParts` (an abort's confirmation); in a versioned bucket
  also `s3:GetObjectVersion` and `s3:DeleteObjectVersion`.
- **Region and endpoint:** `--output-s3-region`, else `AWS_REGION`, `AWS_DEFAULT_REGION` or the profile's,
  else `us-east-1`; the one resolved, and `--output-endpoint-url` (an S3-compatible store, addressed
  path-style), are fixed for the run. The environment's endpoint variables (`AWS_ENDPOINT_URL`,
  `AWS_ENDPOINT_URL_S3`, FIPS, dual-stack) are never applied to the destination; a CA bundle is
  (`AWS_CA_BUNDLE`, or the profile's `ca_bundle`).
- **The store must support conditional writes** (`If-None-Match: *` and `If-Match`): parts and the manifest are
  created only if absent. Backblaze B2 doesn't; an `--output-endpoint-url` on `backblazeb2.com` is refused before
  listing (exit 2). List B2 to a local dataset instead.
- **A lifecycle rule is required:** a part larger than 8 MiB is a multipart upload. A failed or cancelled
  upload is aborted and the abort confirmed, but one that a killed process leaves is not, nor one whose abort
  the bucket refused or did not confirm (the report's `output.remote.aborts_unconfirmed`), and S3 keeps an
  incomplete upload's parts, billed and invisible to listings, until it is aborted. Set a lifecycle rule that
  aborts incomplete multipart uploads (`AbortIncompleteMultipartUpload`, `DaysAfterInitiation` 1 or more) on
  the prefix or the bucket before writing to it.

## Limits and known differences

- Directory buckets (Express One Zone, names ending in `--x-s3`) are refused with exit 2; access points,
  Multi-Region Access Points and Outposts are not supported.
- A prefix is a string prefix: `s3://bucket/logs` covers `logs/` and `logs-old/`.
- The run report estimates request cost at AWS's reference rate only without an endpoint override.
- An S3-compatible store that ends a listing with an empty or short page while keys follow stops the run with
  exit 1, cause `omitted_keys`, once asking again does not bring the keys back. A versions listing
  (`--all-versions`) is not checked, so there such a store makes swath miss keys without an error: compare one
  prefix's object count first ([S3-compatible stores](#s3-compatible-stores)).
