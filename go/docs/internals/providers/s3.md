# S3 (`internal/source/s3`)

## Support and differences

`s3://bucket[/prefix]` supports general-purpose buckets, current objects, and
`--all-versions` for versions and delete markers. Directory buckets, access points and
Outposts are unsupported. S3-compatible endpoints need their own compatibility checks.
[Shared object-store controls](../../operating.md#object-store-requests) cover authentication,
request timeout, retries and admission.

An anchored literal `--include` can narrow the listing prefix. The report estimates request
cost at AWS's reference list rate on the default service; a custom endpoint has no tariff estimate.
The S3 client does not honor `Retry-After`. It applies the shared
[endpoint validation](../clients.md#endpoint-validation). `--anonymous` emits an ignored-credentials note only
for the environment variables described under credentials below.

Root parse errors keep clean roots and hide credential-bearing authorities; directory-bucket
refusals keep the bucket name.

## Provider implementation

**Client** (`internal/source/s3/client`). One client, over the AWS SDK's S3 service client (`service/s3`): the
SDK builds, resolves, signs and sends the request and decodes error answers; the retry policy, the bounded body
and the response parser are swath's. Credentials come from the SDK's `config` module through this package's
resolution (below), fetched before each attempt is counted ([clients.md](../clients.md)).

- *Request:* one GET per attempt through the SDK's ListObjectsV2 (or ListObjectVersions) operation with
  `list-type=2`, `prefix`, `start-after`, `continuation-token`, `max-keys`, `delimiter`, `fetch-owner` and
  `encoding-type=url`. The SDK decodes a minimal empty envelope while swath's scanner decodes the
  captured listing body (*Parsing*, below). Shared retries, body handling, redirects and User-Agent
  wiring are described in [clients.md](../clients.md#what-swath-keeps). A non-200 2xx is an answer,
  using the code in its `<Error>` body or the status text.
- *Endpoints:* the SDK's endpoint resolver; swath passes the region, `--endpoint`, `--path-style`, `--fips` and
  `--dualstack` (the last two only for AWS's own endpoints, unused with a custom endpoint). Tested forms
  (`TestRequestURLs`):
  - virtual-hosted `bucket.s3.REGION.amazonaws.com` (the default);
  - path-style (`-path-style`; the SDK also uses it for bucket names with dots and for IP endpoints);
  - FIPS (`-fips`: `s3-fips.REGION…`) and dual-stack (`-dualstack`: `s3.dualstack.REGION…`), combined here;
  - custom endpoints (`-endpoint`, S3-compatible stores), with a path, kept byte for byte with virtual-host
    addressing and with one trailing slash folded with path-style or no path, as the identity records them;
    admission follows the shared [endpoint validation](../clients.md#endpoint-validation).

  The partitions (the China partition's `*.amazonaws.com.cn`, a FIPS region alias such as `fips-us-east-1`, sent
  to the region's FIPS host) are the SDK's resolver's and not tested here.

  **Not supported:** access points and Multi-Region Access Points (ARNs), S3 Express One Zone directory
  buckets (a bucket name ending in `--x-s3` is refused before any request, exit 2, class `refused`, as Java:
  they do not list in lexicographic order; `TestDirectoryBucketRefused`), Outposts,
  `use_fips_endpoint` and `use_dualstack_endpoint` read from the shared config (use the flags), and
  automatic region redirects.
- *Signing:* the SDK's SigV4 signing with the credentials fetched for the attempt (one lookup per attempt,
  before it is counted, `TestCredentialsRetrievedOncePerAttempt`), plus the session token when the credentials
  have one, and `x-amz-request-payer` with `--request-payer`; `--bearer-token-command` sends
  `Authorization: Bearer` instead (set by the Guard). The SDK signs with its own clock and payload hash and
  makes no clock-skew correction (its retry path is off).
- *Credentials:* `--anonymous` (the flag S3, GCS and Azure Blob share) is authoritative and the only way
  requests go unsigned: nothing is looked up. The warning checks `AWS_ACCESS_KEY_ID`, `AWS_PROFILE` and
  `AWS_SESSION_TOKEN`; it is not a scan of every AWS credential variable. Otherwise the SDK's default chain runs, with `-profile` selecting the shared-config
  profile. The chain covers:
  - environment keys (`AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, `AWS_SESSION_TOKEN`);
  - the shared `config` and `credentials` files and their profiles (`AWS_PROFILE`, `AWS_CONFIG_FILE`,
    `AWS_SHARED_CREDENTIALS_FILE`);
  - IAM Identity Center (SSO) profiles;
  - web identity (`AWS_WEB_IDENTITY_TOKEN_FILE`, `AWS_ROLE_ARN`);
  - `credential_process`;
  - `role_arn` with `source_profile` or `credential_source` (AssumeRole through STS);
  - container credentials (ECS, EKS Pod Identity);
  - EC2 instance roles (IMDSv2).

  `TestCredentialChain` checks swath's option precedence, explicit anonymity and one SDK-chain wiring
  case; `TestCredentialSources` checks STS region wiring against a fake STS, and
  `TestCredentialsRetrievedOncePerAttempt` changes fake credentials and checks the key signing each request.
  These are swath integration checks, not credential-chain conformance tests. **STS region:** the bucket's
  `--region` is the signing region for S3 only; STS uses the environment's or profile's region, else
  `us-east-1`, independently of the bucket region.
  Credentials are cached by the SDK and refreshed before they expire. **Fail closed** (`TestCredentialsFailClosed`,
  `TestCredentialChain`): requests go unsigned only with `--anonymous`; swath does not decide that a chain is
  empty. Without the flag the chain's first lookup runs in `client.New`, waited for up to 30 s (a web-identity
  token file not yet mounted is polled for, `TestRetrieveWaitsForTokenAppearingDuringLookup`), inside the
  command's context, so a signal or deadline ends it; a lookup that fails, whatever the reason (an empty chain,
  whose SDK error names the instance metadata service; a refused grant; an STS outage at start), is a
  `objhttp.CredentialError` (class `auth`, exit 1) and no listing request is sent. Once credentials have been found,
  each request's signing refreshes them as needed, and a refresh that fails transiently (an STS 5xx or
  throttle, a cut connection) is retried, then the range requeued (`TestCredentialOutageRecovers`).
  Credential intent the SDK drops silently is refused before any request, as configured but broken
  (`objhttp.CredentialError`, class `auth`; `TestPartialCredentialsRefuse`): an access key without its secret or the
  reverse (`AWS_ACCESS_KEY_ID`/`AWS_ACCESS_KEY`, `AWS_SECRET_ACCESS_KEY`/`AWS_SECRET_KEY`), a session token
  without both keys, `AWS_ROLE_ARN` without `AWS_WEB_IDENTITY_TOKEN_FILE`; a configuration the SDK cannot load
  (a profile that does not exist, a token file without a role) is class `auth` too. GCS has no such gap: a
  `GOOGLE_APPLICATION_CREDENTIALS` naming a missing file is refused already (`TestADCConfiguredButBroken`).
- *Region:* `-region`, else the SDK's resolution (`AWS_REGION`, `AWS_DEFAULT_REGION`, the profile's
  `region`), else `us-east-1`. A 301 or `AuthorizationHeaderMalformed` answer names the bucket's region in
  the error (`X-Amz-Bucket-Region`).
- *Resume identity* (`source.Identified`): the inputs as given, compared as given: the source (bucket and
  prefix), the endpoint (`--endpoint`, empty for AWS's own; its canonical form folds the scheme and host case, and
  one trailing slash only where the SDK sends the same requests without it: path-style, or an endpoint with no
  path; virtual-host addressing keeps a path as given, so `/base` and `/base/` are two endpoints), the region above, `path style`, `fips`, `dual-stack` and `fetch owner`. Nothing resolves
  them to a URL first: a FIPS region alias is its own value. With no `--region`, the region is what the
  environment or profile resolved, so a resume that resolves another region is refused
  (`TestIdentityRecordsInputs`). A library caller's supplied `Options.Client` is identified by the route it names
  (`s3.Routed`) in place of the endpoint, its path byte for byte, or the run declines resume
  (`TestResumeRefusesEndpointPath`).
- *Retryable failures:* 5xx, 429, `SlowDown` and other S3 throttling codes, `RequestTimeout`,
  retryable connection failures, cut success bodies, attempt deadlines and malformed listing
  documents. Malformed gzip is a terminal read failure, class `other`. Other 4xx answers retain
  typed `*client.Error` diagnostics (status, code, message, request ID). Engine listing calls
  requeue after transient retry exhaustion; [shared retry policy](../clients.md#retry-policy-and-accounting)
  owns attempts, backoff and counters.
- *Shared client plumbing:* [clients.md](../clients.md) owns retries, accounting, credential waits,
  capture, transport construction and [request admission](../clients.md#request-admission). S3 keeps its
  credential resolution, SigV4 and bearer wiring, endpoint resolver settings, response scanner and
  status/code policy. `objhttptest.Contract` runs through this client in `TestRetryContract`;
  `TestAnswers` retains S3-specific diagnostics, cap wiring and answer classification.
- *Overload signals* (`client.Error.Failure`):

  | Answer | Shared limiter input |
  |---|---|
  | 429, any 503, or an S3 throttling code (`SlowDown`, `Throttling`, and the set in `classify.go`) | Throttle |
  | `RequestTimeout` without a throttle signal, or an attempt deadline | Timeout; holds growth, does not cut |
  | Another 5xx or retryable connection failure | Transient; no throttle signal |

  The [shared controller](../clients.md#request-admission) owns permits, slow start and the rate cap.
- *Failures:* [the shared vocabulary](../clients.md) owns normalization, labels and requeue.
  A parsed invalid page keeps `objhttp.ErrInvalidPage`; the engine wraps it as a protocol violation
  (`cause` `protocol`, unresumable; [durability.md](../durability.md)). Unsupported sources are refused
  before listing; caller cancellation retains its stop disposition.
- *Parsing:* [S3 decoding](../clients.md#s3-decoding) owns the scanner contract and its measured
  rationale. Per-page strings share an arena; the scanner URL-decodes keys and common prefixes once and
  keeps version IDs verbatim. Rows retain that arena until encoded; part min/max keys are cloned.

**On the range engine.** S3 lists through `internal/source/keyrange` ([range-engine.md](../range-engine.md)): its page fetch is one
ListObjectsV2 (`start-after` is exclusive, there is no end bound, so the engine trims at `hi`; probes do not
fetch owners), its description adds the client's counters (`attempts`, `retries`, `throttles`, `timeouts`,
`parse_failures`), requeues a transient failure whose retries were exhausted, and wraps contract breaks in
`objhttp.ErrInvalidPage`. `TestRequests` (`internal/source/s3`) pins what the adapter sends: the scope
prefix, a resume's `start-after`, continuations without it, 1,000 keys a page, and the seed's delimiter
listing in its first wave, beside the first data page; a real key's `%` is sent as a start-after. Where ranges split is the engine's policy, tested in `internal/source/keyrange` against the
tiling, resume and sorted-output laws, not frozen in a hash.
