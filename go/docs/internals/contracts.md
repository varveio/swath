# Contracts

What the Go tool promises, by responsibility: what a dataset guarantees to its readers, what each producer
means by its rows, and how a run executes and recovers. Each rule names its mechanism and the test that holds
it ([../testing.md](../testing.md)). Provider-specific rules (S3's `(lo, hi]` ranges, safe pivots, the key
limit) live with the provider ([providers.md](providers.md)); the correspondence with Java's I1–I12 is
migration history, at the end.

## Dataset guarantees (readers rely on these)

| Rule | Mechanism | Test |
|---|---|---|
| **The dataset is SeekParquet.** The manifest and the parts follow SeekParquet format 1 draft revision 1 (`format` `seekparquet`, `format_version` 0, `draft_revision` 1): only its members in the manifest, swath's own under `extensions.swath`; the key declaration `{"column": "key", "unique": …}`, `unique` false exactly for the versions schemas; the five `seekparquet.*` footer stamps equal to the manifest's. | `dataset.Manifest` (its JSON form), the writer's stamps (`parquetout`), `Meta.Groups` from the schema. | `TestManifestShape`, `TestFooterOnlyChange`, the SeekParquet conformance step (the format's reference validator at the full level, [testing.md](../testing.md#seekparquet-conformance)), `verify.py` |
| **The manifest is the commit.** A directory without `manifest.json` holds no dataset; one with it holds exactly the parts it lists, in key order, under `data/`. | `dataset.Publish` installs `manifest.json` last by an atomic rename and a directory sync, after every part is fsynced and renamed. A failed or cancelled run leaves no manifest. | `TestDatasetContract`, `TestPublishFailureLeavesNoManifest`, crash matrix |
| **Coverage is stated.** The manifest's swath extension (`extensions.swath`) says what was listed (`source`, `scope`) and how much of it (`coverage`: complete, stop reason, skipped entries, exclusions, filters, `snapshot: false`). A reader that needs the whole source fails closed on anything less. | Coverage comes from the provider's report; the run report is never part of acceptance. | `TestS3Dataset`, downstream reader probe |
| **Keys are bytes in unsigned order, unique, strictly ascending within and across parts** (for the versions schemas: non-decreasing, a key's rows consecutive and never across parts). Parts are key-disjoint, so they concatenate without a merge. | Every stage checks strict ascent: the provider, the order stage's stream-wide guard on every row (the resumed seam included), the router on each part against the one before it and the journal on each record, both before the part is journaled, the writer, and the publication gate (`*dataset.InvariantError`). | `TestDatasetContract`, `TestOrderGuard`, `TestBoundaryDefectNeverReachesTheJournal`, `verify.py`, `diffds.py` |
| **Part facts are exact.** Each part's `rows`, `bytes`, `min_key_base64`/`max_key_base64` (the first and last key's exact bytes) and MD5 (`extensions.swath.part_md5`) are true; the parts hold every row listed. | The writer measures them; the gate checks counts and order; the row counts are reconciled at the provider, the order stage (received and handed on), the router and the writer before the manifest. | `TestDatasetContract` |
| **The page-index profile.** Footers carry exactly the five `seekparquet.*` stamps and standard `sorting_columns`; 1,024-row pages with column and offset indexes; every column's index bounds are exact (never shortened). | `parquetout` writer constants ([parquet-output.md](parquet-output.md)). | `TestDatasetContract`, `TestKeyLimits`, `TestFooterOnlyChange`, `verify.py`, the conformance step |
| **Parts are immutable.** A published part is never rewritten; a resume verifies retained parts by size and MD5 before continuing. | `recoverParts` (`ErrPartAltered`; a link or non-regular part, or a linked `data/`, is refused unread: `ErrUnsafeLayout`). | crash matrix, `TestAlteredPartIsRefused`, `TestRecoveryRefusesNonRegularPart` |

## Producer semantics (what a row means)

| Rule | Mechanism | Test |
|---|---|---|
| **One row per listed entry, once.** The ranges of a run partition the scope: every key in it is listed by exactly one range, and no key outside it. | Providers split ranges into disjoint children; the order stage drains them depth-first. | S3 T1 random-split tiling, `TestListingEqualsSortedOracle` (filesystem) |
| **S3: every row is a current object** (`swath/s3-objects/v1`); a key ending in `/` is an object; delimiter prefixes are derived, never stored; owner columns are null unless asked for at run start. | `s3.Schema`. | `TestS3Dataset`, `diffds.py` against Java |
| **GCS: every row is a live object** (`swath/gcs-objects/v1`; its current generation, listed by `objects.list` without `versions`); a name ending in `/` is an object; delimiter prefixes are derived, never stored; checksums are base64 as listed and absent fields are null; `time_created` is optional (absent from parts written before it was listed). | `gcs.Schema`, the adapter's row mapping. | `TestRowsCarryEveryField`, `TestClientPagesMatchGoogleClient`, the replay identity with the S3 route ([measurements](../measurements.md#gcs-route-parity)) |
| **Filesystem: one row per entry below the root**, directories included with a named `kind`; names are bytes, never skipped or normalised; symlinks are not followed. | `localfs.Schema`; `getdents64` and portable engines. | `TestListingEqualsSortedOracle`, `TestKeysAreBytes` |
| **A listing is not a snapshot.** Entries that change while it runs may or may not be in it. | `coverage.snapshot` is always false. | – |

## Execution and recovery

| Rule | Mechanism | Test |
|---|---|---|
| **Bounded rows and metadata, not RSS.** Rows and scheduler metadata (child nodes, spill markers) in flight are bounded by `--row-budget`, not by object count, apart from one publish batch per worker, the awaited range's batch and the root-to-frontier path; spill takes ranges ahead of the frontier to disk within its disk budget (default: half the free space); spill readers and encoders are admitted against descriptors and, for encoders, a writer allowance equal to the row budget. `--row-budget` is not a process memory cap ([ordering.md](ordering.md#the-budget)). A waiting range's bounds are copies, never views of a page's buffer, so a range charged as metadata holds only its own bytes ([ordering.md](ordering.md#what-a-waiting-range-retains)). A dry run counts without ordering and holds no rows. | `order.Options.Budget` shared with the encoders' queues; `childUnits`, `markerUnits`; `listing.admitEncoders`; the cursor's copy in `keyrange.expandRange`, `keyrange.detach`; `order.Count`. | `TestDelayedFrontierPlateaus`, `TestDrainerExpandedLeadIsBounded`, `TestSpillReadersAreCapped`, `TestSpillDiskBudget`, `TestRetainedBoundsDoNotPinPages`, `TestCountOnlyHoldsNothing` |
| **No wait on child work; no deadlock on a full buffer.** | Children become claimable; the drainer expands what it awaits itself. | order tests |
| **No cycle; no endless empty chain.** A truncated page needs a continuation token. A continuing page with no entry is followed by its token (object stores may return them); a token that repeats one of the last 1,024 of its run of empty pages is an invalid page (a longer cycle is not detected: the window is bounded memory, not all-time uniqueness). Only the first 1,024 empty pages of a run (`keyrange.EmptyChainLive`) count as progress for the watchdog; past them the pages are still followed, and a service that keeps sending them stops as stuck after `--stall-timeout` (exit 75, `cause` `stuck_empty_chain`, resumable), so a run ends without `--max-duration` unless the watchdog is off (`--stall-timeout 0`). A nonempty page must hold keys strictly ascending past the cursor. | `keyrange.Engine.list` for every request path (ranges, the sequential chain, the seed and structure probes); the order checks in each path; `Engine.Frontier`, the watchdog's `ProgressSnapshot.Liveness`. | `TestEmptyContinuingPages`, `TestFreshEmptyTokensUseBoundedMemory`, `TestEmptyChainFrontier`, `TestEndlessEmptyPagesAreStuck`, `TestT4Paging` |
| **Deterministic output within a build, on one platform class.** The same listing produces byte-identical parts for any worker or encoder count, unless the part interval closed a part by time (`resources.part_time_cuts` > 0). The promise holds for one build on machines of one encoder path: amd64 with AVX2, or every other platform (arm64, amd64 without AVX2). Across the two, the rows, part boundaries, row counts, statistics and key index are the same, but a dictionary-encoded column's page bytes may differ ([parquet-output.md](parquet-output.md#byte-identity)). | Part boundaries depend only on rows apart from interval cuts; column-parallel encoding equals serial; zstd's output does not depend on its assembly. | `TestRouterIsDeterministicAcrossEncoders`, `TestFooterOnlyChange` (a golden per encoder path), gates (same-build MD5s) |
| **Commit before emit.** A part is renamed into `data/` only after its journal record (its `PartInfo` and the writer state) is fsynced. | The router's in-order `Publish` hook, the one ordered committer. | crash matrix, `TestSIGKILLAtEveryPoint` |
| **Durable-prefix recovery.** A resume never emits a published key again and never skips one: it lists after the last recorded part's max key K, or from K's longest prefix the provider accepts as a bound, re-fetching and dropping the keys up to K. On a static source the result is byte-identical to an uninterrupted run; on a live one, durable output is exactly-once. | `swath resume`, `source.Resumable.Restart(K)`; no split or cursor is journaled ([durability.md](durability.md)). | crash matrix, `TestResumeAfterKey`, `TestBoundVetoOnEveryRequest`, `TestSIGKILLResume`, `TestAmbiguousTailRefusesOnChangedSource` |
| **Certified reuse (durable spill).** Above K a resume replays every certificate it accepts and lists only the gaps: a certificate `(cs, ce]` holds exactly the filtered rows of that logical interval as the earlier attempt observed them; certificates lie in their ranges' logical intervals (above K, never a request bound below it), so they are disjoint (I2/I3) and the gaps are their complement; replay emits only `max(cs, K) < k <= ce`. A seal record is appended only after its file and name are synced (I1), and the part journal is never touched; output durability is parts only, and a file outlives its rows until K covers them (I5/I6). The seal is part of a split's return, and children inherit nothing (I4). Slot admission and retirement never wait, replay holds no worker (I7); shutdown keeps retirement alive through the router's close (I8); replay is bounded by its frames and tail (I9); keys are raw bytes throughout (I10); retained bytes count against `--spill-max`, live certificates against the cap, the ledger against H, fence state is O(1) per emitter and every frame is decoded within its bounds (I11); fences are declared only at accepted bounds or K (I12). Retained observation: a key deleted since a certificate stays, one added inside it is missed. | `source.Fencer` fences, `order.Cache` (slots, history, flusher, ledger), `order.RecoverDurable` (prefix, validation, classification), `keyrange.aroundReuse`, `order` replay ranges ([ordering.md](ordering.md#durable-spill)). | `TestDurableCertifiesExactRows`, `TestFencesHoldTheContract`, `TestReuseTilesAroundSpans`, `TestDurableLedgerPrefix`, `TestDurableCorruption`, `TestDurableSpillResume`, the durable kill matrix |
| **One owner per output.** Nothing in the output is read, removed or renamed before the process holds its lock, and nothing is created, written by pathname, removed, renamed or published once a check finds its pathname no longer names the locked directory (a replacement between a check and its action is not excluded). | `journal.TakeLock` before preparation or recovery; `Lock.Verify` (the directory's and lock file's identity, taken with the lock) before the parts directory and each part file are created, each claim and publication rename, recovery's renames and removals, cleanup, each spill file created, appended to or removed and the spill cleanup, the manifest, the outcome and report, and the command's `Progress.Owned` writers (progress, dumps, forced outcome) (`journal.ErrOutputReplaced`). | `TestCompetingRunsAreRefused`, `TestReplacedOutputIsNeverTouched`, `TestReplacedOutputWithLiveWriters` |
| **A frozen identity.** A resume refuses changed schema, writer recipe, part size, key cap or source identity (`*journal.MismatchError`) and a journal of a version it does not read (`*journal.VersionError`: it reads 7 and 8, before recovery changes anything; an opened journal keeps its version). | `journal.Check`, a pure function; `journal.MinVersion`..`journal.Version`. | `TestCheck`, `TestResumeChecksIdentity`, `TestJournalVersions` |
| **Shutdown order.** On cancellation the drainer stops, wakes all waiters, waits for the workers, then the router closes and waits for its encoders; then the durable spill's K callback is detached and its flusher drained and joined, its ledger closed (its directory removed only after a commit's manifest); an interrupted run (a signal, `--max-duration`, `--stall-timeout`) gets 15 s, then the process exits with its code, at most 5 s later whatever blocks (diagnostics to stderr are bounded and dropped). | `order.Run`, `listing` (`closeCache`), `cmd/swath`. | cancellation tests, `TestDurableShutdownOrder` |

## Migration history: Java's I1–I12

The rules above were first stated as Java swath's contracts (`docs/internals/contracts.md` §0 in the Java
tree). Correspondence: I1 commit before emit; I2 one row per entry (no gap, no overlap); I3 the boundary
belongs to the left (`(a, b]`, an S3 rule now in providers.md); I4 a split is atomic with one owner (owner-only
splits, never journaled); I5 and I6 durable-prefix recovery; I7 no wait on child work; I8 shutdown order; I9 no
infinite loop; I10 unsigned byte order; I11 bounded memory; I12 safe pivots (an S3 rule). Java's §4.1
publication order (`_SUCCESS` last) became "the manifest is the commit". Retired as Go requirements: the
`_SUCCESS` ordering, the compound version/row-type sort stamps, the 13-column canonical schema and Java's
schema-string spelling ([../upgrade.md](../upgrade.md)).
