# Contracts

What swath promises, by responsibility: what a dataset guarantees to its readers, what each producer
means by its rows, and how a run executes and recovers. Each rule names its mechanism and the test that holds
it ([testing.md](testing.md)). Provider-specific rules (S3's `(lo, hi]` ranges, safe pivots, the key
limit) live with the provider ([providers.md](providers.md)); the invariants I1–I12 they keep true are [at the end](#the-invariants-i1i12).

## Dataset guarantees (readers rely on these)

| Rule | Mechanism | Test |
|---|---|---|
| **The dataset is SeekParquet.** The manifest and the parts follow SeekParquet format 1 draft revision 1 (`format` `seekparquet`, `format_version` 0, `draft_revision` 1): only its members in the manifest, swath's own under `extensions.swath`; the key declaration `{"column": "key", "unique": …}`, `unique` false exactly for the versions schemas; the five `seekparquet.*` footer stamps equal to the manifest's. | The seekparquet module: `seekparquet.MarshalManifest`/`ParseManifest` for `dataset.Manifest`'s JSON form, `write.NewPart` for the stamps; `Meta.Groups` from the schema. | `TestManifestShape`, `TestFooterOnlyChange`, the SeekParquet conformance step (the format's reference validator and the module's Go validator at the full and digest levels, [testing.md](testing.md#seekparquet-conformance)), `verify.py` |
| **The manifest is the commit.** A directory or bucket prefix without `manifest.json` holds no dataset; one with it holds exactly the parts it lists, in key order, under `data/` (`data/part-NNNNN.parquet` locally, `data/RUN/ATTEMPT/part-NNNNN.parquet` in a bucket; the manifest's paths are authoritative). Failures before the manifest is installed leave no committed dataset. A nonzero exit does not imply that no manifest exists: partial coverage (class `incomplete`), a reporting failure after the commit, or a directory sync that failed after the rename can each coexist with one. | Local output: `dataset.Publish` installs `manifest.json` last by an atomic rename and a directory sync, after every part is fsynced and renamed. Bucket output: the manifest is created only if absent (`dataset.PublishRemote`, a create-only write), after every part is uploaded and, for journaled runs, recorded. | `TestDatasetContract`, `TestPublishFailureLeavesNoManifest`, crash matrix |
| **Coverage is stated.** The manifest's swath extension (`extensions.swath`, `version` 1 first) says what was listed (`source`, `scope`) and how much of it (`coverage`: complete, stop reason, skipped entries, exclusions, filters, `snapshot: false`). The reader hands it on; an application that needs the whole source decides from it. | Coverage comes from the provider's report; the run report is never part of it. | `TestS3Dataset`, `TestManifestShape`, `TestParseMetadataVersion`, downstream reader probe |
| **Keys are bytes in unsigned order, unique, strictly ascending within and across parts** (for the versions schemas: non-decreasing, a key's rows consecutive and never across parts). Parts are key-disjoint, so they concatenate without a merge. | Every stage checks strict ascent: the provider, the order stage's stream-wide guard on every row (the resumed seam included), the router on each part against the one before it and the journal on each record, both before the part is journaled, the writer, and the publication gate (`*dataset.InvariantError`). | `TestDatasetContract`, `TestOrderGuard`, `TestBoundaryDefectNeverReachesTheJournal`, `verify.py`, `diffds.py` |
| **Part facts are exact.** Each part's `rows`, `bytes`, `min_key_base64`/`max_key_base64` (the first and last key's exact bytes) and SHA-256 (`parts[].sha256`) are true; the parts hold every row the listing selected. The manifest's `extensions.swath.committed_object_bytes`, when present, is the `size` column summed over every row of the dataset, each row once (retained, replayed from spill, or listed after a retry); it is absent, never 0, when a part's count is unknown. | The module's part writer measures them (`write.PartWriter.Seal`, the digest computed as the bytes are written); the gate checks counts and order; the row counts are reconciled at the provider, the order stage (received and handed on), the router and the writer before the manifest. swath's writer sums each part's object sizes as it writes the rows (`schema.ObjectSize`), the journal record keeps the count, and the commit sums the parts' (`dataset.ObjectBytes`). | `TestDatasetContract`, `TestCommittedObjectBytes`, `TestCommittedObjectBytesResumed`, `TestCommittedObjectBytesReplayed`, `TestCommittedObjectBytesLegacy` |
| **The page-index profile.** Footers carry exactly the five `seekparquet.*` stamps and standard `sorting_columns`; 1,024-row pages with column and offset indexes; every column's index bounds are exact (never shortened). | `parquetout` writer constants ([parquet-output.md](parquet-output.md)). | `TestDatasetContract`, `TestKeyLimits`, `TestFooterOnlyChange`, `verify.py`, the conformance step |
| **Parts are immutable.** A published part is never rewritten; a resume verifies retained parts by size and SHA-256 before continuing. | `recoverParts` (`ErrPartAltered`; a link or non-regular part, or a linked `data/`, is refused unread: `ErrUnsafeLayout`). | crash matrix, `TestAlteredPartIsRefused`, `TestRecoveryRefusesNonRegularPart` |

## Producer semantics (what a row means)

| Rule | Mechanism | Test |
|---|---|---|
| **One row per selected entry, once.** The ranges of a run partition the scope: every key in it is listed by exactly one range, and no key outside it. A key the filters drop has no row. Split-point and delimiter probes do not emit their sampled rows; the seed can emit rows from its first data page when the remaining scope fits on that page; with `--all-versions` a key has one row per version, generation or snapshot listed. | Providers split ranges into disjoint children; the order stage drains them depth-first. | `keyrange` `TestT1RandomSplitsCoverEveryKeyOnce` random-split tiling, `TestListingEqualsSortedOracle` (filesystem) |
| **S3: every row is a current object** (`swath/s3-objects/v1`); a key ending in `/` is an object; delimiter prefixes are derived, never stored; owner columns are null unless asked for at run start. | `s3.Schema`. | `TestS3Dataset`, `diffds.py` against Java |
| **GCS: every row is a live object** (`swath/gcs-objects/v1`; its current generation, listed by `objects.list` without `versions`); a name ending in `/` is an object; delimiter prefixes are derived, never stored; checksums are base64 as listed and absent fields are null; `time_created` is optional (absent from parts written before it was listed). | `gcs.Schema`, the adapter's row mapping. | `TestRowsCarryEveryField`, `TestClientPagesMatchGoogleClient`, the replay identity with the S3 route ([measurements](measurements.md#gcs-route-parity)) |
| **Filesystem: one row per entry below the root**, directories included with a named `kind`; names are bytes, never normalized or left out for their bytes; symlinks are not followed. | `localfs.Schema`; `getdents64` and portable engines. | `TestListingEqualsSortedOracle`, `TestKeysAreBytes` |
| **A listing is not a snapshot.** Entries that change while it runs may or may not be in it. | `coverage.snapshot` is always false. | – |

## Execution and recovery

| Rule | Mechanism | Test |
|---|---|---|
| **Bounded rows and metadata, not RSS.** Rows and scheduler metadata (child nodes, spill markers) in flight are bounded by `--sort-buffer`, not by object count, apart from one publish batch per worker, the awaited range's batch and the root-to-frontier path; spill takes ranges ahead of the frontier to disk within its disk budget (default: half the free space); spill readers and encoders are admitted against descriptors and, for encoders, an encoder allowance of their own (1/16 of memory, whatever `--sort-buffer` says). `--sort-buffer` is not a process memory cap ([ordering.md](ordering.md#the-budget)). A waiting range's bounds are copies, never views of a page's buffer, so a range charged as metadata holds only its own bytes ([ordering.md](ordering.md#what-a-waiting-range-retains)). A dry run counts without ordering and holds no rows. | `order.Options.Budget` shared with the encoders' queues; `childUnits`, `markerUnits`; `listing.admitEncoders`; the cursor's copy in `keyrange.expandRange`, `keyrange.detach`; `order.Count`. | `TestDelayedFrontierPlateaus`, `TestDrainerExpandedLeadIsBounded`, `TestSpillReadersAreCapped`, `TestSpillDiskBudget`, `TestRetainedBoundsDoNotPinPages`, `TestCountOnlyHoldsNothing`, `TestEncoderAllowance` |
| **No wait on child work; no deadlock on a full buffer.** | Children become claimable; the drainer expands what it awaits itself. | order tests |
| **No cycle; no endless empty chain.** A truncated page needs a continuation token. A continuing page with no entry is followed by its token (object stores may return them); a token that repeats one of the last 1,024 of its run of empty pages is an invalid page (a longer cycle is not detected: the window is bounded memory, not all-time uniqueness). Only the first 1,024 empty pages of a run (`keyrange.EmptyChainLive`) count as progress for the watchdog; past them the pages are still followed, and a service that keeps sending them stops as stuck after `--stall-timeout` (exit 75, `cause` `stuck_empty_chain`, resumable), so a run ends without `--max-duration` unless the watchdog is off (`--stall-timeout 0`). A nonempty page must hold keys strictly ascending past the cursor. | `keyrange.Engine.list` for every request path (ranges, the sequential chain, the seed and structure probes); the order checks in each path; `Engine.Frontier`, the watchdog's `ProgressSnapshot.Liveness`. | `TestEmptyContinuingPages`, `TestFreshEmptyTokensUseBoundedMemory`, `TestEmptyChainFrontier`, `TestEndlessEmptyPagesAreStuck`, `TestT4Paging` |
| **Deterministic output within a build, on one platform class.** The same listing produces byte-identical parts for any worker or encoder count, unless the part interval closed a part by time (`resources.part_time_cuts` > 0). The promise holds for one build on machines of one encoder path: amd64 with AVX2, or every other platform (arm64, amd64 without AVX2). Across the two, the rows are the same, but a dictionary-encoded column's page bytes may differ, and because the router calibrates later part limits from the first part's encoded size and a row group closes on its encoded size, part and row-group boundaries, counts, statistics and the key index may differ too when the sizes do ([parquet-output.md](parquet-output.md#byte-identity)). | Part boundaries depend only on rows apart from interval cuts; column-parallel encoding equals serial; zstd's output does not depend on its assembly. | `TestRouterIsDeterministicAcrossEncoders`, `TestFooterOnlyChange` (a golden per encoder path), gates (same-build digests) |
| **Commit before emit (journaled runs).** In a local output directory, a part is renamed into `data/` only after its journal record (its `PartInfo` and the writer state) is fsynced. In a bucket, a part is uploaded before its claim receipt and journal record are synced and may be visible on its own before them; it is never renamed, and it joins the dataset only through the manifest. K, the recovery point, moves only after the record. | The router's in-order `Publish` hook, the one ordered committer. | crash matrix, `TestSIGKILLAtEveryPoint` |
| **Durable-prefix recovery.** A resume never emits a published key again and never skips one: it lists after the last recorded part's max key K, or from K's longest prefix the provider accepts as a bound, re-fetching and dropping the keys up to K. On a static source the resumed dataset holds the same rows as an uninterrupted run; its parts are byte-identical to that run's only for the same build on the same encoder path without time cuts, and the manifest's timestamps can differ. On a live source, durable output is exactly-once per key below K; above K, replayed certificates keep the earlier observation (next row). | `swath resume`, `source.Resumable.Restart(K)`; no split or cursor is journaled ([durability.md](durability.md)). | crash matrix, `TestResumeAfterKey`, `TestBoundVetoOnEveryRequest`, `TestSIGKILLResume`, `TestAmbiguousTailRefusesOnChangedSource` |
| **Certified reuse (durable spill).** Above K a resume replays every certificate it accepts and lists only the gaps: a certificate `(cs, ce]` holds exactly the filtered rows of that logical interval as the earlier attempt observed them; certificates lie in their ranges' logical intervals (above K, never a request bound below it), so they are disjoint (I2/I3) and the gaps are their complement; replay emits only `max(cs, K) < k <= ce`. A seal record is appended only after its file and name are synced (I1), and the part journal is never touched; output durability is parts only, and a file outlives its rows until K covers them (I5/I6). The seal is part of a split's return, and children inherit nothing (I4). Slot admission and retirement never wait, replay holds no worker (I7); shutdown keeps retirement alive through the router's close (I8); replay is bounded by its frames and tail (I9); keys are raw bytes throughout (I10); retained bytes count against `--spill-budget`, live certificates against the cap, the ledger against H, fence state is O(1) per emitter and every frame is decoded within its bounds (I11); fences are declared only at accepted bounds or K (I12). Retained observation: a key deleted since a certificate stays, one added inside it is missed. | `source.Fencer` fences, `order.Cache` (slots, history, flusher, ledger), `order.RecoverDurable` (prefix, validation, classification), `keyrange.aroundReuse`, `order` replay ranges ([ordering.md](ordering.md#durable-spill)). | `TestDurableCertifiesExactRows`, `TestFencesHoldTheContract`, `TestReuseTilesAroundSpans`, `TestDurableLedgerPrefix`, `TestDurableCorruption`, `TestDurableSpillResume`, the durable kill matrix |
| **One owner per output.** Preparation, recovery and mutations hold the output lock. Read-only journal-header and witness checks can precede it. Nothing is created, written by pathname, removed, renamed or published once a check finds its pathname no longer names the locked directory (a replacement between a check and its action is not excluded). | `journal.TakeLock` before preparation or recovery; `Lock.Verify` (the directory's and lock file's identity, taken with the lock) before the parts directory and each part file are created, each claim and publication rename, recovery's renames and removals, cleanup, each spill file created, appended to or removed and the spill cleanup, the manifest, the outcome and report, and the command's `Progress.Owned` writers (progress, dumps, forced outcome) (`journal.ErrOutputReplaced`). | `TestCompetingRunsAreRefused`, `TestReplacedOutputIsNeverTouched`, `TestReplacedOutputWithLiveWriters` |
| **A frozen identity.** A resume refuses changed schema, writer recipe, part size, key cap or source identity (`*journal.MismatchError`) and a journal of a version it does not read (`*journal.VersionError`): this build writes journal version 10 and reads versions 9 and 10 (both record SHA-256; 10 adds a bucket dataset's object names and destination); versions below 9 or above 10 are refused before recovery changes anything. The metadata readers (`swath show`, `--seed-from`) read a manifest whose `extensions.swath.version` is 1, within `dataset.ManifestLimits`, and refuse any other version or none; `Managed` recognizes any manifest of swath's. | `journal.Check`, a pure function; `journal.MinVersion`..`journal.Version`. | `TestCheck`, `TestResumeChecksIdentity`, `TestDurableVersions`, `TestInteriorCorruptionFailsClosed`, `TestManifestShape` |
| **Shutdown order.** On cancellation the drainer stops, wakes all waiters, waits for the workers, then the router closes and waits for its encoders; then the durable spill's K callback is detached and its flusher drained and joined, its ledger closed (its directory removed only after a commit's manifest); an interrupted run (a signal, `--max-duration`, `--stall-timeout`) gets 15 s, then the process exits with its code, at most 5 s later whatever blocks (diagnostics to stderr are bounded and dropped). | `order.Run`, `listing` (`closeCache`), `cmd/swath`. | cancellation tests, `TestDurableShutdownOrder` |

## The invariants I1–I12

This table owns the load-bearing invariants. Every rule above exists to keep one of them true; a change that
weakens one needs an adversarial test ([testing.md](testing.md)). The numbering is stable, so tests and
comments cite it.

| # | Invariant | Where it holds |
|---|---|---|
| I1 | **Commit before emit.** In a journaled run, nothing joins the dataset before the record that makes it recoverable is durable: in a local output directory a part is renamed into `data/` only after its journal record is fsynced; in a bucket a part may be visible as an object first, but the manifest names only journaled parts and is written after every one. | [Commit before emit](#execution-and-recovery), [durability.md](durability.md) |
| I2 | **Keyspace partition.** The ranges of a run are pairwise disjoint and cover the scope: every key is listed by exactly one range, none outside it. | [One row per listed entry](#producer-semantics-what-a-row-means), [range-engine.md](range-engine.md) |
| I3 | **The boundary belongs to the left.** A range is `(a, b]`: it emits keys `k <= b`, and its right neighbour starts after `b`. | [range-engine.md](range-engine.md) |
| I4 | **A split is atomic, with one owner.** A range is split only by the worker that owns it, at a page boundary, against the cursor it has; splits are never journaled. | [range-engine.md](range-engine.md) |
| I5 | **Durable-prefix recovery.** A resume lists after the last recorded part's max key, never emitting a published key again and never skipping one. | [Durable-prefix recovery](#execution-and-recovery) |
| I6 | **Durable output.** A journaled part is recoverable once its bytes and claimed name are durable and its journal record is acknowledged; recovery completes a missing publication rename. A dataset is committed when its manifest exists. | [The manifest is the commit](#dataset-guarantees-readers-rely-on-these) |
| I7 | **No wait on child work.** A worker never holds its slot while waiting for work it handed on, so the scheduler cannot deadlock on itself. | [ordering.md](ordering.md), [clients.md](clients.md) |
| I8 | **Shutdown order.** Consumers stop and wake their waiters before producers are joined; the process exit is bounded. | [Shutdown order](#execution-and-recovery) |
| I9 | **Progress checks.** Invalid ordering, a missing continuation token and a detected token repetition are protocol errors (`source.ErrProtocol`, cause `protocol`). Empty continuing pages are followed with a bounded token history (the last 1,024 tokens); an endless empty chain with fresh tokens is stopped by the liveness watchdog (`--stall-timeout`, cause `stuck_empty_chain`) when it is enabled. | [clients.md](clients.md), the provider pages |
| I10 | **Byte-exact keys.** Keys are bytes in unsigned order end to end: compare, split, journal and Parquet. | [Keys are bytes](#dataset-guarantees-readers-rely-on-these) |
| I11 | **Bounded reorder storage.** Object-store reorder buffers and scheduler metadata are budgeted independently of the total object count, apart from the in-flight exceptions under [Bounded rows and metadata](#execution-and-recovery); per-part metadata grows with the number of parts. A local walk also holds each directory's entries while it reads them, so one large directory can exceed `--sort-buffer`. | [ordering.md](ordering.md) |
| I12 | **Safe split pivots.** A synthesized pivot lies strictly between its bounds and introduces no code point a store may refuse in a start bound (controls, noncharacters, `%`); which real keys may be sent as a bound is the provider's policy. | [range-engine.md](range-engine.md), [providers.md](providers.md) |
